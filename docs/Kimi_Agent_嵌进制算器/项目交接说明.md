# 嵌入式混合进制计算器 — 项目交接文档

> 面向接手开发的 agent：本文档包含项目目标、已确定的设计决策、当前实现状态和待办路线。所有"已决策"条目都是与需求方逐轮确认过的结论，不要推翻；如需改动先与需求方确认。

## 1. 项目目标

为嵌入式开发者打造的轻量计算器。**核心场景**：嵌入式开发频繁混用 2/10/16 进制，需要直接输入混合进制的 C 语法算式，如：

```
x1A + b0110 ^ u2 << 2
```

**产品形态**：Svelte 前端 + Tauri v2 打包为本地桌面应用。硬性要求：**响应迅速、体积极小**（当前原型 gzip 后约 18KB，零运行时依赖——保持这个水平，禁止引入 mathjs 等大型求值库）。

**与现有工具的差异化**（调研结论：此组合无先例）：算式中**每个数字**（而非仅结果）都有多进制视图、逐数字垂直对齐、光标在数字内部可按 ↑/↓ 单独切换该数字的显示进制。参考过 QCalc、hexowl、xalc、pcalc、SpeedCrunch，它们都只做"结果"的进制转换。

## 2. 技术栈

- 前端：Svelte 5（runes 模式）+ Vite 6 + JavaScript（暂未启用 TS，正式版建议迁移）
- 求值：纯手写 lexer + Pratt parser + BigInt，位于 `src/lib/calc.js`，无 UI 依赖、可单测
- 桌面壳：Tauri v2（尚未接入）
- 持久化：计划用 tauri-plugin-store（纯 Web 预览退化为 localStorage）；数据仅本地，无云同步

## 3. 已确定的语法规范

### 数字字面量（双轨制）

| 写法 | 进制 |
|---|---|
| `x1A` / `0x1A` | 十六进制 |
| `b0110` / `0b0110` | 二进制 |
| `d42` / `42` / `u7` | 十进制 |
| 数字内允许 `_` 分隔符（如 `b1111_0000`） | — |

**词法消歧规则**：前缀字母（x/b/d/u）后紧跟该进制的合法数字字符才视为字面量。

### 变量（低优先级，未来做）

变量一律 `$` 前缀（`$ans`、`$foo`）。裸标识符不存在，因此 `x1A` 这类写法零歧义。`$` 同时保留 `$0x10`（引用历史记录）等扩展空间。

### 运算符与优先级（遵循 C）

一元 `~ - +` > `* / %` > `+ -` > `<< >>` > `&` > `^` > `|`，支持括号。

### 求值语义

- 全程 BigInt；全局位宽开关 8/16/32/64，每次运算后按位宽掩码截断（无符号回绕语义）
- 移位量取低 6 位；除零/取模零报错
- 负数中间结果按位宽二补码截断显示为无符号值

## 4. 已确定的界面布局（核心设计决策）

整体自上而下：**标题行（含位宽选择器）→ 预设样例按钮 → 输入行（输入框 + 右侧并列的结果区）→ 进制视图区**。

### 4.1 输入框

- 单行，混合进制原文显示
- 数字被切到二进制时：**完全展开所有有效位、无前导零、不折叠**，过长则横向滚动
- 输入框是编辑态，所见即所得

### 4.2 结果区

- **与输入框右侧并列**（flex 行：输入框 flex:1，结果区 min-width 240px / max-width 42%），不独占一行
- 三行显示 hex / dec / bin（bin 小号绿色、单行分组）

### 4.3 进制视图区（本项目的视觉核心）

**"就地三行堆叠"模型**：每个数字 token 是一个 inline-block 列，块内自上而下单行 hex、单行 dec、多行 bin；运算符在 hex/dec 两行重复出现，使这两行各自连续可读。列宽 = 该数字三种显示宽度的最大值（`width: max-content`，行内 `text-align: right` 实现），**只被自己撑宽，不影响其他数字**。

bin 区规则：

- 窄字体（当前用 `font-size: 0.72em` 实现；打磨项是嵌入仅含 `0`/`1`/`_` 三个字形的 condensed 等宽字体子集，woff2 约几 KB）
- 每行最多 8 位（4+4 分组），高位行在上、低位行在下
- **块内右对齐 + 行带内底对齐**。由此得到两个免费性质：
  1. 同一数字内 bit i 恒在从右数第 (i mod 8) 列，行号 = ⌊i/8⌋
  2. 同一行带内所有数字的 bit N 在同一水平线上，可横向比较掩码位模式
- 超宽时**协同换行**：以 token 块为单位 flex-wrap，所有行在同一边界一起折，绝不让 bin 单独折行导致对应关系丢失

**已否决的方案**：按位宽定宽（空白过多）、游程折叠 `[0×5]0110`（被窄字多行方案取代，不做）。

## 5. 已设计但未实现：光标模型与进制切换

这是下一个迭代的重点，设计已定：

- **输入框不用原生 `<input>`**，改为 keydown 接管 + 自绘光标（绝对定位竖条）。理由：原生字符偏移无法表达"数字内部的位"。算式输入几乎纯 ASCII，IME 兼容性可接受
- **逻辑光标 = (tokenId, digitIndexFromRight)**，从右数第几位，与显示进制解耦
- 光标在数字内部时按 ↑/↓：循环切换该数字在输入框中的显示进制（hex → bin → dec）
- **位置保持**：进制间按位等价换算——hex 第 n 位 ↔ bin 第 4n 位（覆盖 bit [4n, 4n+3]）；dec 与 bit 不对齐，退化为从右序号 clamp
- **位置记忆**：每个 token 维护 `{hex, bin, dec}` 三份位记忆，切回时恢复，不用全局换算
- **键位冲突规则**：光标在数字内部 → ↑/↓ 切进制；不在数字上 → ↑/↓ 翻历史记录
- 联动高亮：光标落在某数字/某位时，视图区对应的数字块、对应 nibble（hex 第 n 位 ↔ bin 第 ⌊n/2⌋ 行的 4 位组）同步高亮。换行点固定在 8 的倍数，nibble 永不跨行，映射永远干净
